# 🔄 مدل ذخیره‌سازی روی توکن و رفع باگ «اتصال هست ولی داده ذخیره نمی‌شود»

## مشکل چه بود؟

اپ فقط توکن را **اعتبارسنجی** می‌کرد (`GET /user`) و همان را «اتصال موفق» نشان می‌داد،
اما مسیر واقعی نوشتن/خواندن داده چند ایراد اساسی داشت:

| # | باگ | نتیجه‌ای که کاربر می‌دید |
|---|-----|--------------------------|
| ۱ | فرض «یک Gist مشترک برای هر دو نفر». توکن فقط روی Gistهایی که **مالکشان است** اجازه‌ی `PATCH` دارد. | نوشتن سمت پارتنر با ۴۰۴ شکست می‌خورد. |
| ۲ | `MoodViewModel` هر بار `moods.json` را با **یک رکورد** بازنویسی می‌کرد. | کل تاریخچه‌ی حال روزانه پاک می‌شد. |
| ۳ | هیچ‌جا داده‌ای از Gist **خوانده و وارد دیتابیس** نمی‌شد (`TODO: pull from partner gist`). | داده‌ی پارتنر هرگز نمی‌آمد. |
| ۴ | چت، تقویم، و بقیه‌ی بخش‌ها اصلاً همگام نمی‌شدند. | فقط لوکال می‌ماندند. |
| ۵ | `GitHubGist.description` غیرقابل‌null تعریف شده بود، ولی GitHub برای Gist بدون توضیح `null` برمی‌گرداند. | خطای serialization و شکست خاموش لیست Gistها. |
| ۶ | فایل‌های بزرگ‌تر از ~۱ مگابایت `truncated` برمی‌گردند و محتوایشان خالی است. | داده‌ی ناقص. |
| ۷ | نبود بررسی scope. توکن بدون `gist` کامل احراز هویت می‌شود ولی هیچ‌وقت نمی‌تواند بنویسد. | «اتصال ✅» ولی ذخیره‌سازی ❌. |
| ۸ | خطاهای GitHub با پیام عمومی «خطا در ذخیره‌سازی (کد X)» پنهان می‌شدند. | عیب‌یابی غیرممکن. |

## معماری جدید

```
        دستگاه A                                دستگاه B
   ┌──────────────┐                        ┌──────────────┐
   │   Room DB    │                        │   Room DB    │
   └──────┬───────┘                        └──────┬───────┘
          │ push (توکن A)                         │ push (توکن B)
          ▼                                       ▼
   ┌──────────────┐                        ┌──────────────┐
   │  Gist مال A  │◄──── pull (توکن A) ────│  Gist مال B  │
   │ CoupleOS-... │────► pull (توکن B) ───►│ CoupleOS-... │
   └──────────────┘                        └──────────────┘
```

- هر توکن **صاحب Gist خودش** است، پس نوشتن همیشه مجاز است.
- چون اپ **هر دو توکن** را دارد، می‌تواند هر دو Gist را بخواند.
- ادغام دو سند = تصویر کامل دنیای مشترک.

### فایل‌های داخل هر Gist

| فایل | نقش |
|------|-----|
| `coupleos_snapshot.json` | **منبع اصلی** — کل داده‌های اپ در یک سند |
| `moods.json`, `memories.json`, `messages.json`, `calendar.json`, `tasks.json`, `journal.json` | نسخه‌ی خوانا برای مرور در مرورگر |
| `healthcheck.json` | فایل تست سلامت (نوشتن/خواندن) |
| `README.md` | توضیح داخل Gist |

### حل تعارض (Conflict resolution)

برای هر مجموعه، رکوردها بر اساس `id` گروه می‌شوند و رکوردی برنده است که
`updatedAt` (یا در نبودش `createdAt`) بزرگ‌تری دارد — یعنی **آخرین نوشته برنده است**.

### عملیات‌ها

| عملیات | توضیح |
|--------|-------|
| `push()` | ساخت snapshot از Room و نوشتن روی Gist خودم |
| `pull()` | خواندن هر دو Gist، ادغام با داده‌ی لوکال، نوشتن در Room |
| `sync()` | اول `pull` بعد `push` — تا داده‌ی پارتنر پاک نشود |
| `pushQuietly()` | push بی‌صدا بعد از هر تغییر (اگر همگام‌سازی خودکار روشن باشد) |

## چطور مطمئن شوم واقعاً ذخیره می‌شود؟

۱. **تنظیمات → تست کامل ذخیره‌سازی روی توکن.** این تست به‌ترتیب چک می‌کند:
   - توکن ذخیره شده؟
   - احراز هویت GitHub موفق؟
   - scope `gist` وجود دارد؟
   - Gist ساخته/پیدا شد؟ (شناسه‌اش نمایش داده می‌شود)
   - نوشتن یک فایل آزمایشی موفق بود؟
   - همان فایل دوباره خوانده شد و محتوایش درست بود؟
   - توکن و Gist پارتنر سالم است؟

۲. **برچسب روی هر آیتم**: «☁️ روی توکن» یعنی ذخیره شده، «📱 فقط لوکال» یعنی هنوز نه.

۳. **مرورگر**: به `https://gist.github.com` برو؛ باید یک Gist خصوصی با توضیح
   `CoupleOS-SharedData` ببینی.

## توکن درست چطور ساخته می‌شود؟

**Classic token** (ساده‌ترین راه):
`GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)`
→ فقط تیک **`gist`** را بزن.

**Fine-grained token**:
در بخش *Account permissions* گزینه‌ی **Gists** را روی **Read and write** بگذار.

> اگر توکن scope `gist` نداشته باشد، اپ همان لحظه‌ی ورود توکن هشدار می‌دهد.
